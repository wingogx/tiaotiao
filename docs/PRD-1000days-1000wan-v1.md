# 1000天赚到1000万实盘记录站 PRD

## 1. 文档信息

- 文档版本：`v1.0`
- 创建日期：`2026-05-11`
- 产品阶段：`第一版 / MVP`
- 项目目标：以尽量低的日常录入成本，持续记录“1个人，1000天赚到1000万”的真实过程，并提供会员查看能力。

## 2. 产品定位

这是一个兼具公开展示与会员内容访问能力的个人实盘记录网站。

产品有两个核心目标：

- 对外：作为公开落地页，展示挑战目标、阶段进展和最近内容，吸引用户注册与关注。
- 对内：作为个人经营管理工具，每天记录项目收入、任务完成情况和复盘文章。

第一版重点不是做复杂系统，而是保证以下原则：

- 每天录入动作简单，控制在几分钟内完成。
- 大部分统计数据自动计算，不依赖手工汇总。
- 结构清晰，方便后期逐步开放更多会员内容页面。

## 3. 第一版范围

### 3.1 要做的内容

- 公开首页 / 落地页
- 邮箱登录
- 管理员手动授权会员角色
- 会员查看文章正文
- 项目管理
- 每日收入登记
- 每日任务清单
- 每日文章发布
- 自动生成当日任务清单
- 基础进度统计与展示

### 3.2 第一版不做的内容

- 在线支付
- 成本、利润、退款等财务维度
- 多币种
- 富文本编辑器
- 附件上传
- 历史日期收入补录
- 未完成任务自动继承到次日
- 复杂任务状态流转
- 多管理员协作
- 会员自助购买与自动开通

## 4. 用户角色与权限

### 4.1 角色定义

- `guest`：游客，未登录用户
- `member`：会员，已登录且被管理员授权
- `admin`：管理员，唯一操作用户

### 4.2 权限范围

`guest`

- 可访问公开首页
- 可查看文章标题、日期、封面、摘要
- 不可查看文章正文
- 不可进入后台与会员区功能页

`member`

- 可访问公开首页
- 可查看文章列表
- 可查看文章正文
- 第一版暂不开放项目、任务、收入、进度等内部管理页

`admin`

- 拥有全部管理权限
- 可管理项目、任务模板、当日任务、收入记录、文章、会员角色

说明：后续如要开放更多页面给会员，按页面维度逐步放开即可。

## 5. 产品结构

第一版建议采用如下结构：

- `/`：公开首页，同时作为轻量落地页
- `/login`：邮箱登录页
- `/articles`：文章列表页
- `/articles/:slug`：文章详情页
- `/app/today`：今日录入区，仅管理员可用
- `/app/projects`：项目管理页，仅管理员可用
- `/app/tasks`：任务管理页，仅管理员可用
- `/app/progress`：完成进度页，仅管理员可用
- `/app/income`：收入情况页，仅管理员可用
- `/app/users`：用户与会员授权页，仅管理员可用

导航顺序按业务约定为：

- 首页
- 项目看板
- 任务跟踪
- 完成进度
- 收入情况
- 每日文章

说明：对游客和会员，前期只实际开放首页与文章相关页面；其余页面先保留为后台结构，后续按角色开放。

## 6. 核心业务对象

### 6.1 项目

项目指当前并行推进、可能带来收入的子项目，例如：小红书、视频号、知识星球等。

项目规则：

- 可创建
- 可修改名称与基础信息
- 可关闭
- 仅在没有任何收入记录时可删除
- 一条收入记录必须归属于某个项目

### 6.2 收入记录

收入按“当天”登记，且只能登记当天数据。

收入规则：

- 支持一天登记多条收入
- 金额可为正，也可为负
- 币种统一为 `CNY`
- 每条收入必须绑定一个项目
- 保存或修改后，相关汇总数据立即自动更新
- 第一版不支持历史日期补录

### 6.3 任务

任务用于每日执行与复盘，只保留最简单状态。

任务规则：

- 状态仅有 `已完成` 与 `未完成`
- 任务清单由固定任务、项目任务、临时任务组成
- 当日任务可多次勾选并提交
- 未完成任务不自动继承到第二天
- 每天保留完成数、未完成数、完成率统计

### 6.4 文章

文章用于每日复盘、收获与思考记录。

文章规则：

- 不是必须每天发布
- 支持封面图
- 内容采用 `Markdown`
- 管理员可复制粘贴内容后提交
- 游客可见标题、日期、封面、摘要
- 会员可见正文

## 7. 页面需求

### 7.1 首页

定位：公开落地页，偏展示与吸引，不做过重的数据堆叠。

目标：

- 让游客快速理解项目主题
- 建立长期挑战感与真实记录感
- 引导用户注册 / 登录
- 展示最新内容入口

建议展示内容：

- 项目标题：`1000天赚1000万 实盘跟踪日记`
- 起始日期：`2026-05-12`
- 当前第几天
- 累计收入
- 总目标金额
- 目标进度
- 最近 `5` 篇文章标题
- 登录 / 注册入口

首页要求：

- 风格直观、简洁、美观
- 不展示太细的后台经营数据
- 文章标题点击可进入文章详情页

### 7.2 项目看板

定位：管理员维护当前收入来源项目。

核心功能：

- 项目列表展示
- 创建项目
- 修改项目名称与基础信息
- 关闭项目
- 删除无收入项目

建议字段：

- 项目名称
- 状态：`进行中 / 已关闭`
- 创建日期
- 备注
- 累计收入（自动计算）
- 收入记录数（自动计算）

项目任务相关：

- 可为项目设置“每日任务模板”
- 可为项目设置“指定日期任务模板”
- 这些任务模板将参与生成当日任务清单

### 7.3 任务跟踪

定位：管理员每日执行清单与复盘清单。

任务来源：

- 固定任务模板
- 项目每日任务模板
- 项目指定日期任务模板
- 当日临时新增任务

核心功能：

- 查看当日任务清单
- 勾选任务完成状态
- 多次保存当日任务状态
- 新增当日临时任务
- 查看当日完成数、未完成数、完成率

任务展示建议：

- 任务名称
- 所属来源：固定 / 项目 / 临时
- 所属项目（如有）
- 复选框

### 7.4 完成进度

定位：展示长期挑战的总体推进情况。

核心内容：

- 总天数：`1000`
- 起始日期：`2026-05-12`
- 当前第几天
- 剩余天数
- 时间进度
- 收入进度
- 目标差额

第一版要求：

- 以自动计算为主
- 数据来源于系统配置与收入汇总
- 不要求复杂图表，但要清楚直观

### 7.5 收入情况

定位：查看收入录入与自动汇总结果。

核心功能：

- 新增当天收入记录
- 编辑当天收入记录
- 删除当天收入记录
- 查看当天收入合计
- 查看按项目汇总的累计收入
- 查看总累计收入

规则说明：

- 仅允许录入当天日期
- 每次修改后自动重算汇总

### 7.6 每日文章

定位：展示复盘内容，兼顾公开与会员访问。

列表页要求：

- 默认按时间倒序显示
- 可展示封面、标题、日期、摘要
- 游客可访问列表

详情页要求：

- 游客可见基础信息与摘要
- 会员登录后可见正文

第一版不要求：

- 附件
- 图文混排编辑器
- 评论
- 点赞

### 7.7 今日录入

定位：管理员每天最常使用的轻量入口。

页面仅保留三块内容：

- 记收入
- 勾任务
- 写文章

设计目标：

- 尽量减少跳转
- 保证每天 3-5 分钟内完成录入
- 保存后自动同步到项目、收入、文章、进度等页面

## 8. 任务自动生成规则

### 8.1 生成时间

系统每天 `01:00` 自动生成当日任务清单。

### 8.2 生成来源

当日任务清单由以下数据组合而成：

- 固定任务模板：每天都生成
- 项目每日任务模板：每天生成
- 项目指定日期任务模板：仅在匹配日期生成

### 8.3 临时任务

管理员可在当日任务清单中手动追加临时任务。

### 8.4 兜底逻辑

若定时生成失败，系统在管理员当天首次进入“今日录入”或“任务跟踪”时，自动检测并补生成当天任务清单，确保不会因为定时任务异常导致当天无清单可用。

### 8.5 状态规则

- 默认状态为 `未完成`
- 勾选后为 `已完成`
- 支持一天内多次修改与提交
- 当天结束后保留统计结果

## 9. 关键计算逻辑

### 9.1 全局目标

- 起始日期：`2026-05-12`
- 总天数：`1000`
- 总目标收入：`10,000,000 CNY`

### 9.2 自动计算项

- 当前第几天
- 剩余天数
- 时间进度
- 总累计收入
- 当日收入合计
- 各项目累计收入
- 收入进度
- 距离目标差额
- 当日任务完成数
- 当日任务未完成数
- 当日任务完成率

### 9.3 收入口径

- 以管理员当天录入并保存的 `income_records` 为准
- 支持正负金额
- 修改后实时更新相关统计

## 10. 数据录入原则

第一版强调低负担录入。

管理员日常仅需操作三类数据：

- 当天收入记录
- 当天任务勾选结果
- 当天文章内容

其余数据尽量自动汇总、自动派生，不要求重复填写。

## 11. 技术方案原则

### 11.1 总体建议

- 新开项目实现第一版
- 复用当前已部署域名与站点入口
- 当前旧项目不再继续叠加开发

原因：

- 旧项目是静态看板结构，不适合继续扩展会员权限和数据录入逻辑
- 新项目可从一开始按“公开区 + 会员区 + 后台”结构组织
- 更利于后期维护与扩展

### 11.2 后端建议

第一版建议使用 `Supabase`，用于：

- 邮箱登录
- 用户角色存储
- 项目、任务、收入、文章数据存储
- 定时任务生成能力

### 11.3 登录方式

- 仅支持邮箱登录
- 会员权限由管理员手动开通
- 第一版不接支付能力

## 12. 第一版成功标准

满足以下条件即可认为第一版可上线：

- 游客可访问公开首页并理解产品定位
- 游客可浏览文章标题与摘要
- 用户可通过邮箱登录
- 管理员可手动授予会员权限
- 会员可查看文章正文
- 管理员可创建、修改、关闭项目
- 管理员可登记当天收入并自动汇总
- 管理员可查看并维护当日任务清单
- 系统可自动生成当日任务清单
- 管理员可发布文章并在首页展示最近 5 篇标题

## 13. 后续迭代方向

以下内容不进入第一版，但可作为后续规划：

- 逐步开放更多会员区页面
- 支付与会员购买流程
- 更细粒度的角色权限控制
- 项目与文章、项目与收入的更强关联展示

- 图片管理与更完整的文章编辑体验

- 首页公开

- 会员内容前期以文章正文为主
- 权限采用 `guest / member / admin`
- `admin` 唯一且拥有全部操作权限
- 会员由管理员手动授权
- 仅支持邮箱登录
- 不做支付
- 项目收入必须归属项目
- 收入只录当天，支持多条、支持正负值
- 任务状态仅有已完成与未完成
- 未完成任务不自动继承
- 每天 `01:00` 自动生成任务清单，并保留补生成兜底机制
- 项目支持每日任务模板与指定日期任务模板
- 今日录入区只保留收入、任务、文章三块
- 文章支持封面与 Markdown 内容
- 游客可见标题与摘要，会员可见正文
